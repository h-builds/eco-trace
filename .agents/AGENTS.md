# Execution Order Enforcement

## Strict Execution Ordering
When working on tasks defined in `TASKS.md` or `PLAN.md` files:
- **NEVER** start or execute a task that is marked with a higher Execution Order `(N)` until **ALL** tasks with a lower Execution Order number are fully completed and checked off.
- Even if the user explicitly asks you to start or complete a task (e.g., "Update the anatomy", "Do Section 10"), you MUST first check the Execution Order annotations. If the task depends on lower-numbered tasks that are not yet complete, you must politely refuse and inform the user of the unmet dependencies.
- You must read the dependencies column in the "Execution Order Summary" table to verify blockers before beginning work on any section.
